# OKX 虚拟交易观察台

本地运行的多币种行情分析与虚拟积分交易 Demo。自动扫描 OKX 公共行情，展示筛选原因、技术信号、模拟持仓和回测结果。项目不会连接 OKX 交易账户，也不会提交订单。

## Windows 软件包（桌面版 + 网页版）

发布文件为 `release/Pulse-Trading-Demo-0.3.0-win-x64.zip`。在 Windows 10/11 x64 解压整个文件夹，双击 `Pulse.exe` 即可使用，无需安装 Node.js、pnpm 或 Python。

- `Pulse.exe` 打开桌面界面；`打开网页版.cmd` 或菜单“软件 → 在浏览器打开网页版”打开普通浏览器。桌面与浏览器连接同一本机服务，共用账户、持仓和成交。
- 地址使用自动分配的本机空闲端口，可在“帮助 → 关于与网页版地址”中查看。只监听 `127.0.0.1`，不对局域网和公网提供服务。重复启动会复用已有实例。
- 保持桌面软件运行；关闭窗口或点击“退出软件”会关闭本地服务，浏览器随后离线。停止期间不会模拟成交，重启后先获取新鲜行情。
- 数据位于 `%APPDATA%\PulseTradingDemo`，配置为其中的 `settings.env`；菜单可打开目录及配置。保存配置后重启。升级时替换软件文件夹即可，用户数据仍保留；删除软件文件夹也不会主动删除账户。
- 包内不包含开发者 `.env`、密钥、真实/测试数据库或开发环境；首次运行创建独立的 10,000 虚拟积分账户。原源码网页版默认数据库仍为项目的 `data/trader.sqlite`，不会自动导入桌面账户。
- 本地构建未配置应用代码签名证书。如系统拦截，先核对来源与 ZIP 的 SHA256，不要关闭系统安全防护。包内保留 Electron/Chromium 许可证和图表归属标识。

软件包旁的 `.sha256` 校验 ZIP，包内 `build-manifest.json` 记录源码和各文件的校验值。备份桌面账户请先退出软件，再复制整个用户数据目录；重置仍需界面确认。真实行情需要网络，离线样本不需要外部行情网络。

## 现货与 USDT 永续

页面顶部可切换“现货 / USDT 永续”。两个市场各自自动扫描最多 20 个合格币种，切换同时更换价格、图表、信号、账户、历史回测和 CSV；不需要逐个切换币种。选择保存在当前浏览器中，桌面与普通浏览器可以分别查看不同市场，后台持续管理两个市场的持仓。

价格均为对应 OKX 产品的最新成交价 `last`：现货 `BTC-USDT`，USDT 永续 `BTC-USDT-SWAP`。对比欧意 App 时使用同一个产品与最新成交价，并注意报价时间；标记价、指数价与现货不是同一口径。价格实时变化，无法保证两个屏幕在任意时刻逐位相同。5 分钟图表与策略仍使用已收盘 K 线。

每个市场单独拥有 10,000 初始虚拟积分、自动入场开关、持仓、历史、权益与重置。现货沿用原 `trader.sqlite`；永续使用同目录 `trader.swap.sqlite`（自定义 DATABASE_PATH 时在扩展名前加 `.swap`）。切换页面不暂停另一市场；重置只清除当前市场。升级 0.2.0 的现货账户不会被重建或当作永续持仓。

永续仅接入加密类别（`instCategory=1`）、正常交易规则（`ruleType=normal`）、USDT 结算、基础币面值的线性合约，面值和乘数必须可验证（当前支持乘数 1）；股票、商品、币本位、盘前及类别未知合约不进入此池。按 [OKX 官方字段单位](https://www.okx.com/docs-v5/en/)，永续 ticker 的基础币成交量乘最新价用于估算 24h USDT 成交额，界面明确标“估算”；盘口张数乘每张基础币面值后计算 USDT 深度；K 线使用基础币量。现货成交额和盘口保持原口径。

永续采用真实合约行情与基础币等值数量进行**无杠杆虚拟模拟**，费用、滑点、名义仓位和风控沿用本 Demo 的模拟参数；未模拟资金费、保证金、强平及交易所张数步长，不能视为完整合约账户。离线回放始终是固定合成样本，与两个实时账户都隔离。

所有市场接口和 WebSocket 使用 `?market=spot` 或 `?market=swap`，省略时沿用现货。例如 `/api/snapshot?market=swap`、`/api/backtest?market=swap`、`/api/trades.csv?market=swap` 与 `/ws?market=swap`。开平仓、重置和自动开关必须携带目标市场；现货、永续的持仓 ID 只在各自账户内有效。非法市场或与市场不符的交易对直接拒绝。

重新打包与检查：

```sh
pnpm package:win
pnpm smoke:desktop
node scripts/desktop-smoke.mjs --real
```

打包需要 Windows x64、开发依赖及内置 Electron 44.7.2 的下载网络；已下载且通过 SHA256 校验的运行时可离线复用。使用 Electron 官方的[预编译运行时打包结构](https://www.electronjs.org/docs/latest/tutorial/application-distribution)，下载失败时可用 npmmirror，始终核对固定版本 SHA256。桌面检查实际解压 ZIP、去掉 Node/pnpm PATH、从含空格且非源码的目录启动 EXE，验证页面加载、共享服务、重启恢复、单实例、独立回测、费用与正常退出清理；`--real` 另测包内实际 OKX 连通。检查使用独立临时账户，不操作日常账户。

## 源码网页版启动

需要 Node.js 24（包含内置 SQLite）及 pnpm 11。在本项目目录打开 PowerShell，首次运行：

```powershell
node --version
pnpm --version
if (!(Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
pnpm install --frozen-lockfile
pnpm dev
```

开发页面地址：`http://127.0.0.1:5173`（端口占用时以终端打印的地址为准）；后端健康检查：`http://127.0.0.1:3001/api/health`。OKX 公共行情无需密钥；默认配置即可扫描。第一次筛选可能需要几十秒，页面会显示连接和加载状态。

构建与启动：

```sh
pnpm build
pnpm start
```

默认数据库位于 `data/trader.sqlite`，请勿将 `.env` 或数据库提交到版本库。

生产页面直接打开 `http://127.0.0.1:3001`，无需另开 Vite。修改 `.env` 的 `PORT` 后，生产页面和后端改用该端口，开发代理也会同步；修改配置需要重启。服务默认仅监听本机。按 `Ctrl+C` 停止服务，停止期间不会管理虚拟持仓，重新启动后取得新鲜行情再继续处理。

## 使用顺序

1. 等待“实时扫描中”，直接查看自动筛选的所有候选与信号；搜索或点选币种只改变详情图表。
2. 查看排除原因和模拟规则，再手动虚拟做多/做空；需要自动模拟时点击“开启自动入场”。启动后等待新的 5 分钟收盘信号及下一笔报价，不会立即追逐旧信号。
3. 在持仓区查看止盈止损及浮动盈亏，可手动平仓；暂停自动入场后旧持仓仍会管理。成交后可导出 CSV。
4. “回测当前候选”自动抓取整个当前候选池；“打开离线样本回放”可在外部行情断网时体验固定样本，两者使用独立账户。
5. 重置按钮需在弹窗确认，会清空当前虚拟持仓、成交和统计，并关闭自动入场。数据不应被当作可恢复的交易凭证。

## 自动扫描

后端每 30 分钟重新发现 OKX USDT 现货交易对，每分钟刷新候选币种的 5 分钟 K 线。价格优先订阅 OKX 公共 `tickers` WebSocket，自动跟踪候选和已有持仓币种；连接失败、心跳超时或订阅失败会退避重连并重新订阅，默认用每秒一次 REST 轮询兜底（`MARKET_POLL_MS=1000`）。推送健康时每 30 秒 REST 对账；行情请求单独排队，不会被历史回测分页阻塞。`OKX_WS_URL` 可按适用地区配置，留空仅使用轮询。

界面每秒更新最新有效报价，展示交易所时间（到毫秒）、报价年龄及“推送/轮询”来源。报价只在收到真实更新时改变；心跳和页面时钟不会刷新报价时间，行情无变化或网络故障时不能保证每秒都有新价。迟到、重复、非法或过远未来的报价不会覆盖有效新价；逐币超过 15 秒无有效报价会禁用成交。网页本地连接状态和交易所行情来源分别显示。高频推送即时管理风控，但行情快照最多每秒一次；价格增量不重复携带全部 K 线，权益采样也限为每秒一次（成交事件强制记录）。

筛选通过后按 24 小时成交额取前 20 个。首页自动显示候选和排除原因，无需手动选择币种。稳定币基础币按默认已知名单排除，其中包含 USDG；可通过 `SCREEN_EXCLUDED_STABLE_BASES` 设置逗号分隔的完整排除名单。该名单不能保证识别所有稳定币。使用默认 [OKX WebSocket 443 地址](https://my.okx.com/docs-v5/log_en/)，不依赖计划停用的 8443 端口。

筛选阈值可在 `.env` 设置。默认要求上市至少 90 天、24 小时成交额至少 1,000 万 USDT、买卖价差不超过 0.2%、中间价上下 0.5% 范围的双侧盘口名义深度各至少 10 万 USDT；5 分钟价格波动超过 5% 则暂停该币种入场 30 分钟。筛选依据是交易状态、流动性和数据可靠性，不代表对币种项目本身的信誉判断。

`GET /api/snapshot` 返回扫描和连接状态、候选币种及 K 线；`GET /api/pairs` 返回筛选结果；`GET /api/candles/BTC-USDT` 返回入选币种的 K 线；`/ws` 推送同一快照。状态为 `loading`、`stale` 或 `error` 时不得据此执行模拟入场。

每个候选币种只用已收盘的 5 分钟 K 线计算 EMA9、EMA21 和 RSI14。EMA9 高于 EMA21 且 RSI14 高于 50 为 LONG；反之 EMA9 低于 EMA21 且 RSI14 低于 50 为 SHORT，其余为 WAIT。K 线不足或存在时间缺口时不输出指标。同一币种的同一根已收盘 K 线仅发出一次信号事件，重启后也不会重复发出。

## 虚拟交易计算

虚拟账户初始为 10,000 积分，积分按 OKX 的 USDT 报价等比例计价，但不能兑换或转出。`POST /api/trades/open` 可手动模拟开仓（JSON：`{"symbol":"BTC-USDT","side":"LONG"}` 或 `SHORT`）；`POST /api/trades/:id/close` 手动平仓。`POST /api/auto` 使用 `{"enabled":true}` 开启自动入场，默认关闭；关闭后旧持仓仍按实时价格检查止盈止损。`POST /api/account/reset` 必须提交 `{"confirm":true}`；该操作清空虚拟持仓和交易记录并恢复 10,000 积分。`GET /api/account` 查看账户，`GET /api/trades.csv` 导出交易。

入场和退出均按不利滑点处理，再扣各自手续费。默认滑点 0.05%、单边手续费 0.1%，可通过 `.env` 修改。止损距成交入场价 1%、止盈距入场价 2%。单笔预计亏损最多当前权益的 1%，所有持仓的预计止损风险合计最多 3%，同时最多 3 个持仓，总名义仓位不超过当前权益。做空只是本地数学模拟，不涉及借币、保证金或资金费。跳空会按恢复后的可用报价成交，实际模拟亏损可能超过预计风险。

自动交易只处理启用后新收盘的信号，并在下一笔新鲜行情到来时执行；同一根 K 线不会重复入场。交易引擎对照数据库中的信号和已处理记录，在重启或通知丢失后恢复未处理信号。行情超过 15 秒未更新时不发生新的模拟成交。

## 开源组件选择

使用 [Fastify](https://github.com/fastify/fastify) 提供服务，[React](https://github.com/facebook/react) 和 [Lightweight Charts](https://github.com/tradingview/lightweight-charts) 展示网页与行情，[technicalindicators](https://github.com/anandanand84/technicalindicators) 计算 EMA 与 RSI。行情使用 OKX 官方 REST 接口。完整交易框架如 [Freqtrade](https://github.com/freqtrade/freqtrade) 以 Python 为主，直接引入会改变既定应用结构和虚拟积分交易规则，因此本项目复用适合的组件，实时和回测共用 TypeScript 交易计算。允许与 Python 模块互通，当前 Demo 不额外要求 Python。

## 回测、离线回放与统计

网页的“回测当前候选”自动抓取所有当前合格币种的历史 5 分钟已收盘 K 线，可选每币 300 或 600 根。`POST /api/backtest` 使用 `{"source":"historical","bars":300}`。历史接口按照 OKX [分页规则](https://www.okx.com/docs-v5/trick_en/#pagination) 向过去翻页、去重，并剔除未收盘数据。数据缺口会明确拒绝，抓取失败的币种会在结果中列出。多币种起止时间不齐时，只使用所有币种共同覆盖的连续窗口，并显示截取提示；共同窗口不足 31 根或时间未对齐会拒绝，绝不拿缺价币种的旧价格延长回测。实际根数和日期以返回结果为准。

信号只使用当时已经收盘的数据，预热至少 30 根后在下一根开盘成交。入场尺寸、滑点、手续费和盈亏复用实时函数。开盘跳过止损/止盈价时按开盘处理；同根同时碰到止损和止盈按止损优先；反向信号先平仓，下一根再判断入场；共同窗口最后统一按收盘价平仓。同根开盘退出后不再重新入场。K 线不能还原逐笔路径，因此回测退出是明确的近似假设。

回测从独立的 10,000 虚拟积分账户开始，不读写实时账户的持仓、余额或成交。历史盘口、价差、上市名单和当时全市场候选池未还原；只模拟连续 K 线及短时波动筛选。今天入选的币种会产生选择偏差，不能把结果称为历史全市场回测。多币种信号按当时已收盘 K 线量价估算的成交额排序（最多过去 24 小时），不引用今天成交额替代历史。

“打开离线样本回放”使用固定合成 BTC/ETH/SOL 样本，完全不需要行情网络。支持播放、暂停、单步和进度拖动；显示当时的样本持仓、成交和权益。该区域始终标为离线样本，并与实时扫描区分开。接口为 `POST /api/backtest`、`{"source":"replay"}`。

统计显示收益率、最大回撤、胜率、平均盈利/亏损、Profit Factor。无交易或分母为零时显示“不适用”。实时回撤采用持久化的新鲜行情权益采样；历史采用每根收盘权益，可能漏掉采样之间的低点。持仓缺价时权益和浮动盈亏暂按入场价估算，收益率不提供，回撤不纳入该估值。重置同时清除权益采样。

## 可选 AI 解读

AI 默认未配置，全部行情与虚拟交易功能仍可使用。只在后端 `.env` 设置 `OPENAI_API_KEY` 和你要使用的 `OPENAI_MODEL` 后重启服务；`OPENAI_BASE_URL` 留空使用官方 `https://api.openai.com/v1`，自定义时应填写提供 Responses 接口的基础地址（含 `/v1`）。网页从不接收或返回密钥。

点击“请求 AI 解读”才调用 [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)，发送的内容仅为公开候选行情与技术指标，不发送虚拟账户或交易记录。每次最多 700 输出 token，20 秒超时，只允许 1 个并发请求且间隔至少 3 秒。请求可能产生所配置服务的 API 费用；未配置、网络失败、超时或模型错误只返回解读错误，不阻塞交易。AI 文本不能修改策略或风控。

## 验证与常见问题

```sh
pnpm test
pnpm smoke
```

`pnpm test` 验证指标、筛选、重试、去重、交易计算、风险边界、回测时间及 AI 异常。`pnpm smoke` 先构建，再启动本机受控行情和独立临时账户，检查生产首页、REST/WS、多币种筛选、多空入场、重启恢复、价格止损、统计、CSV、旧价拒绝、确认重置与回测隔离，结束后自动清理自己的服务和临时数据库。它不调用真实 OKX 或付费 AI，也不会清空默认数据库。真实行情连通证据另列在验收记录中。

| 现象 | 处理 |
| --- | --- |
| 找不到 `pnpm` 或 Node 版本不足 | 安装 Node.js 24 与 pnpm 11 后重新打开终端；不要使用旧版 Node 的 SQLite 替代实现。 |
| 提示 SQLite experimental warning | Node 的内置模块提示；若健康检查正常，可继续运行。 |
| 端口被占用 | 修改 `.env` 的 `PORT`；开发页面使用 Vite 实际打印的地址，生产页面使用修改后的后端端口。 |
| OKX 连接异常、行情过期或暂时零候选 | 查看页面原因及终端日志，确认网络和适用地区的 OKX 公共 REST 地址；系统会退避重试。可继续运行独立离线样本，不会将样本冒充实时行情。 |
| 自动入场开启后没有立即成交 | 需等启用后的新收盘信号、新鲜报价和风控额度；WAIT、暂停筛选、重复信号或额度不足不会入场。 |
| 回测报缺口、共同窗口不足或抓取失败 | 等待数据恢复后重试，或先使用离线样本；回测不会补造缺失 K 线。 |
| AI 尚未配置或调用失败 | 交易继续可用；检查后端变量及服务是否支持 Responses。不要把密钥贴到网页或验收日志。 |

备份账户时先停止服务，再备份 `DATABASE_PATH` 所在的数据库文件及仍存在的 `-wal`/`-shm` 文件；恢复使用相同路径配置。数据库从旧阶段启动会自动创建新增的统计表。图表使用 [TradingView Lightweight Charts](https://www.tradingview.com/lightweight-charts/)，其内置 TradingView 标识予以保留。
